GIẢI THÍCH CẤU TRÚC FRONTEND APP CHAT REALTIME

Tổng quan
Đây là một cấu trúc frontend cho ứng dụng chat realtime viết bằng React. Cách tổ chức này chia code theo:
- phần khởi động ứng dụng
- từng màn hình
- từng tính năng nghiệp vụ
- phần gọi API
- phần realtime SignalR
- store quản lý state toàn cục
- component dùng chung
- hooks custom
- utility và hằng số

Mục tiêu của cấu trúc này là:
- dễ mở rộng khi app lớn dần
- tách rõ UI, state, service, business logic
- dễ bảo trì
- dễ chia việc cho nhiều người

==================================================
1. CÁC FILE Ở ROOT
==================================================

package.json
- Là file khai báo thông tin project Node.js.
- Chứa:
  + tên project
  + version
  + scripts để chạy app, build app
  + dependencies như react, react-router, redux toolkit, axios, signalr...
- Khi chạy npm install hoặc npm run dev thì hệ thống đọc file này.

vite.config.js
- Là file cấu hình cho Vite.
- Dùng để:
  + cấu hình dev server
  + alias đường dẫn
  + proxy API nếu cần
  + cấu hình build
- Vì project này dùng Vite thay vì Create React App, nên Vite sẽ là công cụ build/dev chính.

.env.development
- File biến môi trường dùng cho môi trường development.
- Ví dụ:
  + VITE_API_BASE_URL=http://localhost:5000
  + VITE_SIGNALR_URL=http://localhost:5000/chatHub
- Dùng khi chạy local để frontend biết gọi backend nào.

.env.production
- File biến môi trường dùng cho môi trường production.
- Ví dụ:
  + VITE_API_BASE_URL=https://api.example.com
  + VITE_SIGNALR_URL=https://api.example.com/chatHub
- Giúp tách cấu hình local và production.

index.html
- Là file HTML gốc mà Vite dùng để mount ứng dụng React vào.
- Trong đó thường có một thẻ như:
  <div id="root"></div>
- React sẽ render toàn bộ app vào đây.

Dockerfile
- File mô tả cách đóng gói frontend thành container Docker.
- Dùng khi deploy.
- Thường sẽ:
  + build app React
  + copy file build vào nginx hoặc server tĩnh
- Giúp deploy nhất quán ở nhiều môi trường.

4. THƯ MỤC features/

Đây là phần rất quan trọng.

- Slice Redux quản lý state liên quan đến xác thực.
- Ví dụ state:

  + access token
  + trạng thái loading
  + lỗi đăng nhập

  + initialState
  + reducers

authSelectors.js
- Chứa các hàm lấy dữ liệu từ auth state.

  + tránh đọc trực tiếp state ở nhiều nơi
  + dễ tái sử dụng

roomsSelectors.js

  + selectRoomsLoading

RoomList.jsx

- Ví dụ:

  + phòng đã join

CreateRoomModal.jsx
- Modal tạo phòng chat mới.
- Có thể có input:

RoomSettingsModal.jsx
- Modal chỉnh sửa cài đặt phòng.

4.3 features/chat/

chatSlice.js
- Quản lý state liên quan đến tin nhắn.
- Ví dụ:
  + danh sách tin nhắn theo room
  + trạng thái loading tin nhắn
  + phân trang / infinite scroll
  + tin nhắn đang gửi
  + trạng thái typing
  + unread count
- Trong app realtime, slice này rất quan trọng vì message đến liên tục từ SignalR.

chatSelectors.js
- Selector cho phần chat.
- Ví dụ:
  + selectMessagesByRoom
  + selectTypingUsers
  + selectUnreadCount

MessageList.jsx
- Component hiển thị danh sách tin nhắn.
- Có thể map qua từng message và render MessageItem.
- Thường xử lý scroll xuống cuối, load thêm tin nhắn cũ, phân nhóm theo ngày.

MessageItem.jsx
- Component hiển thị 1 tin nhắn riêng lẻ.
- Có thể gồm:
  + avatar người gửi
  + tên người gửi
  + thời gian gửi
  + nội dung tin nhắn
  + trạng thái seen/delivered
- Tách riêng để dễ tái sử dụng và tối ưu render.

MessageInput.jsx
- Ô nhập tin nhắn.
- Có thể gồm:
  + textarea/input
  + nút send
  + upload file
  + emoji picker
- Ngoài gửi tin nhắn còn có thể bắn sự kiện typing realtime.

TypingIndicator.jsx
- Component hiển thị kiểu:
  “A đang nhập...”
  hoặc
  “A, B đang nhập...”
- Dữ liệu thường đến từ SignalR hoặc state tạm thời.

Ý nghĩa của features:
- gom logic theo tính năng
- người mới vào project nhìn là biết auth nằm đâu, chat nằm đâu, rooms nằm đâu
- phù hợp project trung bình đến lớn

6. THƯ MỤC services/
==================================================

Đây là lớp giao tiếp với backend hoặc hệ thống bên ngoài.

apiClient.js
- Tạo axios instance dùng chung.
- Thường cấu hình:
  + baseURL
  + timeout
  + headers mặc định
  + interceptor gắn token
  + interceptor xử lý lỗi 401/403
- Mục tiêu là tất cả service khác dùng chung một client thống nhất.

authService.js
- Chứa các hàm gọi API liên quan đến auth.
- Ví dụ:
  + login
  + register
  + refreshToken
  + logout
  + getProfile

roomService.js
- Chứa các hàm gọi API liên quan tới phòng chat.
- Ví dụ:
  + getRooms
  + createRoom
  + updateRoom
  + deleteRoom
  + addMember
  + removeMember

messageService.js
- Chứa các hàm gọi API liên quan tới tin nhắn.
- Ví dụ:
  + getMessagesByRoom
  + sendMessage
  + editMessage
  + deleteMessage
  + markAsRead

signalrService.js
- Phần rất quan trọng cho realtime.
- Dùng để:
  + tạo kết nối SignalR Hub
  + start connection
  + reconnect
  + subscribe event
  + unsubscribe event
  + invoke method lên server
- Ví dụ các event:
  + ReceiveMessage
  + UserTyping
  + UserOnline
  + RoomUpdated

Ý nghĩa của services:
- tách phần gọi API khỏi UI
- component không cần biết chi tiết axios request
- dễ test, dễ đổi backend

- Có thể gói các thao tác:

Ý nghĩa của hooks:
- tái sử dụng logic

- làm component gọn hơn

==================================================
10. CÁCH CÁC PHẦN PHỐI HỢP VỚI NHAU
==================================================

Ví dụ luồng đăng nhập:
1. User nhập thông tin ở LoginPage.jsx
2. LoginPage gọi authService hoặc dispatch async thunk trong authSlice
3. authService dùng apiClient gửi request tới backend
4. Backend trả về token và user info
5. authSlice cập nhật Redux store
6. tokenStorage giữ token trong memory
7. router điều hướng sang ChatPage
8. PrivateRoute cho phép truy cập vì user đã đăng nhập

Ví dụ luồng tải phòng chat:
1. ChatPage mount
2. dispatch action loadRooms
3. roomService gọi API qua apiClient
4. roomsSlice cập nhật state
5. RoomList render danh sách phòng

Ví dụ luồng nhận tin nhắn realtime:
1. useSignalR mở kết nối qua signalrService
2. Backend push event ReceiveMessage
3. signalrService bắt event
4. dispatch action vào chatSlice
5. MessageList tự render lại danh sách tin nhắn mới

Ví dụ luồng user đang gõ:
1. User nhập trong MessageInput
2. Frontend gửi event typing qua SignalR
3. Backend broadcast cho các user khác trong cùng room
4. Frontend bên kia nhận event
5. chatSlice cập nhật typing state
6. TypingIndicator hiển thị “đang nhập...”

==================================================
12. PHÂN BIỆT MỘT SỐ PHẦN DỄ NHẦM
==================================================

Page và Component khác nhau thế nào?
- Page là màn hình lớn gắn với route
- Component là phần nhỏ tái sử dụng trong page hoặc feature

Service và Slice khác nhau thế nào?
- Service gọi API / SignalR
- Slice giữ state và cập nhật state

Hook và Utility khác nhau thế nào?
- Hook dùng khi có logic gắn với React lifecycle hoặc state
- Utility là hàm thuần, không phụ thuộc React

common component và feature component khác nhau thế nào?
- common component dùng ở nhiều nơi, mang tính generic
- feature component gắn với nghiệp vụ cụ thể như MessageList hay RoomSettingsModal

==================================================
14. KẾT LUẬN
==================================================

Đây là một cấu trúc frontend khá hợp lý cho ứng dụng chat realtime dùng React + Redux Toolkit + React Router + Axios + SignalR.

Hiểu ngắn gọn như sau:
- src/main.jsx: khởi động app
- App.jsx: component gốc
- pages/: các màn hình
- features/: từng nhóm chức năng nghiệp vụ
- app/store.js: Redux store
- app/router.jsx: định tuyến
- services/: gọi API và realtime
- hooks/: logic tái sử dụng
- components/: UI dùng lại
- utils/: helper và hằng số

Nếu bạn nhìn theo luồng phát triển thực tế:
- UI nằm ở pages/components/features
- dữ liệu và state nằm ở slices/store/selectors
- giao tiếp backend nằm ở services
- logic tái sử dụng nằm ở hooks/utils

Nhờ cách tách này, app sẽ dễ phát triển hơn khi số lượng tính năng tăng lên.
